## 第一步：理解前端问题

收集问题信息：
- 什么不工作（页面加载、UI 元素、交互）
- 浏览器控制台错误
- 用户操作和预期结果
- 是否影响所有用户或特定用户

## 第二步：启动前端测试器

使用 dev-browser 技能进行浏览器自动化测试：

```
使用 dev-browser 技能调试 AI-Bridge 前端。

后端 URL: http://localhost:8080（或配置的端口）
前端 URL: [用户提供或从配置推导]

调查内容：
1. 导航到前端 URL
2. 检查页面加载和渲染
3. 打开浏览器开发者工具（控制台、网络）
4. 检查控制台错误和警告
5. 监控网络请求（API 调用、WebSocket 连接）
6. 检查 WebSocket/SSE 连接状态
7. 测试失败的用户交互
8. 验证 UI 元素显示和行为
9. 检查 CORS 问题（控制台和网络标签）

提供：
- 控制台错误和警告（完整消息）
- WebSocket 连接状态（连接/断开/错误）
- 网络请求/响应（状态码、头、体）
- UI 行为观察（截图、描述）
- CORS 错误（如找到）
```

## 第三步：常见前端问题

### WebSocket 连接失败
- **症状**：控制台显示 "WebSocket connection failed"
- **常见原因**：
  - 后端未运行
  - 端口不匹配
  - CORS 配置错误
  - Socket.IO 版本不兼容

### API 错误
- **症状**：控制台显示 HTTP 错误（404、500、CORS）
- **常见原因**：
  - 后端端点不存在
  - 认证令牌缺失或无效
  - 请求格式错误
  - CORS 配置问题

### UI 不更新
- **症状**：数据更改但页面不更新
- **常见原因**：
  - SSE 流断开
  - 消息订阅失败
  - 前端状态管理问题
  - 增量同步问题（seq 编号）

### 页面加载失败
- **症状**：空白页或部分内容缺失
- **常见原因**：
  - JavaScript 错误
  - 资源加载失败（CSS、JS）
  - 路由配置问题

## 第四步：浏览器测试模式

**功能测试：**
1. 创建新 session
2. 发送消息
3. 查看 stream 更新
4. 测试权限处理
5. 检查 slash 命令列表

**性能测试：**
1. 大量消息 session（100+ 消息）
2. 增量同步（测试 seq 编号）
3. 长时间连接稳定性

**兼容性测试：**
1. 不同浏览器（Chrome、Firefox、Edge）
2. 不同网络条件
