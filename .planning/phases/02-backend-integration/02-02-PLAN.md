<task type="auto">
  <name>Create Zod schemas and TypeScript types for API responses</name>
  <files>web/src/types/api.ts</files>
  <action>
    Create web/src/types/api.ts with Zod schemas for all backend responses:

    1. **Session schema** (from backend API docs in CLAUDE.md):
       ```typescript
       SessionSchema = z.object({
         id: z.string(),
         status: z.enum(['idle', 'processing', 'waiting', 'stopped']),
         createdAt: z.string(), // ISO datetime
         metadata: z.record(z.unknown()).optional(),
       })
       ```

    2. **Message schema** (for incremental sync):
       ```typescript
       MessageSchema = z.object({
         seq: z.number(), // Monotonically increasing sequence number
         role: z.enum(['user', 'assistant', 'system']),
         content: z.string(),
         timestamp: z.string(),
       })
       ```

    3. **Permission schema**:
       ```typescript
       PermissionSchema = z.object({
         requestId: z.string(),
         sessionId: z.string(),
         operation: z.string(),
         resources: z.array(z.string()),
         scope: z.enum(['file-read', 'file-write', 'command-exec', 'network']),
       })
       ```

    4. **Command schema**:
       ```typescript
       CommandSchema = z.object({
         path: z.string(), // e.g., "/commit"
         category: z.string(),
         description: z.string(),
         examples: z.array(z.string()),
       })
       ```

    5. Export inferred TypeScript types:
       ```typescript
       export type Session = z.infer<typeof SessionSchema>
       export type Message = z.infer<typeof MessageSchema>
       export type Permission = z.infer<typeof PermissionSchema>
       export type Command = z.infer<typeof CommandSchema>
       ```

    CRITICAL: Use flexible validation for status fields (z.string() instead of strict enum) to handle backend changes. Type assertions can narrow types after validation if needed.

    Reference RESEARCH.md > Pattern 2: API Service Layer with Zod Validation.
  </action>
  <verify>File exists with all 4 schemas defined and TypeScript types exported</verify>

       - Returns parsed Session[] or throws error
    4. Create React hook `useSessions()`:
       - Uses useQuery with queryKey: ['sessions']

       - Uses useMutation with mutationFn accepting { workingDir, model }
       - POSTs to /api/v1/sessions
       - Validates response with SessionSchema
       - Calls queryClient.invalidateQueries(['sessions']) on success
       - Returns mutation result

    Follow pattern from RESEARCH.md > Pattern 2 exactly.
