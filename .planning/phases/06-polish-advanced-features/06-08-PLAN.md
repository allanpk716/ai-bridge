## Notes

**Root Cause Analysis:**
原始计划(06-01, 06-02)创建了功能完整的组件,但放在了错误的目录(`src/` 而非 `web/src/`)。这导致组件无法在 Web 应用中使用。

**Solution Options:**
1. **移动组件** (推荐):将 `src/features/search` 和 `src/features/export` 移动到 `web/src/features/`
2. **路径别名** (当前方案):配置 Vite 支持 `@/features` 指向 `../src/features`
3. **符号链接**:在 `web/src/features` 创建指向 `../../src/features` 的符号链接

**Why Task 1 uses path alias:**
- 最小化代码变更
- 保持组件在 `src/` 的组织结构(可能用于其他项目)
- 避免移动文件时的 git 历史问题

**Alternative Approach (if path alias fails):**
如果 Vite 路径别名配置复杂,直接移动组件到 `web/src/features/`:

```bash
# Move search components
mv src/features/search web/src/features/

# Move export components
mv src/features/export web/src/features/

# Update imports in moved files
find web/src/features -name "*.ts" -o -name "*.tsx" | xargs sed -i 's|@/lib/api|@/lib/api|g'
```
